仅凭 PDF 无法判断是图表错误、目标集描述错误还是不同数据源混用。不要只改图注使其看起来一致；先恢复原始证据链，再重新生成图表与对应 Findings。

### 5. VCT 的执行性定义与实际证据层级没有完全对齐

**位置：第 130–134、136、138、140 页。性质：方法与结果口径需要统一。**

方法规定通过 benign control、可重复触发安全违规、在 clean state 上复现两次，才能成为 validated target；结果却明确把 runtime tests 和 source-based checks 都纳入 precision 与修复统计。

执行了一个扫描源代码的脚本，不等于动态证明漏洞可利用或利用已被阻断。目前读者无法判断高 precision 中有多少来自运行时漏洞确认。

**建议修改：**至少区分 Runtime-confirmed、Source-supported、Inconclusive，报告各自数量、oracle 和结果。源代码检查可以保留，但主要“可利用性”和“exploit blocked”结论须匹配相应证据。若用汇总结果，增加分层统计或敏感性分析。

还应明确 rejected/FP 的裁决：有限攻击未复现不自动证明报告错误。对无法排除测试不足的情况，应保留 inconclusive；若判 FP，应说明源码/路径/前置条件审查如何支持该结论。

### 6. 第 5 章需要重写“相似度—修复正确性—安全性”的关系

**位置：第 88–99 页，特别是 5.2.2、5.2.3、5.4。性质：定义冲突及结论超出证据。**

第 88 页写“vulnerability-free only if it satisfies all four dimensions”，但第 89 页又说 Element-Level Relevance 只关注未修好漏洞的输出。把辅助相关性指标当作安全成立的必要条件，与这一适用范围相互冲突。

第 99 页使用 Exact Match 判断漏洞消除，并称其确保修复正确。与一个参考片段一致能够证明参考一致性；不能由不一致直接推出未修复，也不能省略上下文、功能与安全验证。

ELRM 的主要证据是与人类/LLM 评分的相关性，且其组成主要是词法信号。高相关性支持“更接近本研究的评分标准”，尚不足以直接建立“验证了漏洞消除”。

**建议修改：**分别定义代码可用性、功能保持、安全修复判定、参考相关性；ELRM 作为辅助评估信号。补足 FixCap 的安全 oracle、人工评分 rubric 与实际核验数量。如无法补实验，收窄到“reference-based assessment in vulnerability-repair tasks”，避免将相似度写成安全证明。可补充仅改变关键鉴权调用、危险 API 或安全常量的近邻案例，检查指标能否区分安全与不安全实现。

### 8. ELRM 的统计论证需要收紧，并隔离 tokenizer 的贡献

**位置：第 95–97 页，表 5.3–5.5。性质：明确表述错误及统计证据不足。**

第 96 页把 t = 0.54 称为“marginal significance”，这一表述不能由该统计量支持。模型均值有差异，也不等于指标具有稳定性、有效性或 robustness；标准差较大本身更不能证明稳定。

表 5.4 中，采用 ELRM tokenizer 的 BLEU 与 LLM 评分相关系数为 0.804，完整 ELRM 为 0.816，差值为 0.012。因此，当前结果需要区分“改进 tokenization 带来的贡献”和“新增评分组成带来的贡献”。

**建议修改：**给出样本量、配对单位、自由度、p 值、置信区间和效应量；非显著结果据实写。比较相同 tokenizer 下的指标，并提供逐组件消融和权重来源。人评实验也加入相同 tokenizer 的 BLEU 对照。若保留稳定性主张，应提供重复性或排名稳定性证据；同源变体的相关性分析应考虑原始漏洞层面的依赖。

## 二、逐章还应补强的内容

### 第 1–2 章：把总论点写成能够逐章验证的主张

**研究假设，第 3–4 页。** 当前“用 expose/evaluate/mitigate 的方法，使漏洞 observable/assessable/reducible”更像研究目标，较难判断何种结果会否定它。可改成一个 thesis statement，再列三个可核查的问题：资源覆盖了什么；评估方法比基线多提供了什么有效信息；经确认的项目漏洞在何种指导和预算下改善、付出什么功能代价。

在绪论加一张证据映射表：

| 研究部分 | 主要产物 | 当前能支持的结论 | 不宜直接推出 |
|---|---|---|---|
| 第 4 章 | CVE-linked、多提示粒度资源 | 提供结构化实验材料与覆盖统计 | 已证明某种粒度更安全 |
| 第 5 章 | CFCEval、ELRM、变换实例 | 在所测样本上提供多维评估与评分相关性证据 | 高相似度即安全；变换已消除训练污染 |
| 第 6 章 | LLMGProjects、DCRV、受控指导/迭代研究 | 在固定测试和研究范围内评估检测及修复结果 | 普遍模型排名、绝对安全、单独的范围因果效应 |

**术语，第 10 页。** “four generation granularities”列 function/file/requirement/project，却遗漏第 4 章核心的 class-level；requirement 是任务组织方式，与 function/file/project 的产物范围也不完全同轴。建议分开定义 artifact scope 和 prompting/task organization，并统一 requirement/module 的使用。

第 2 章可减少通用模型史，补充后文真正依赖的概念：CVE 与 CWE 的不同计数单位、检测与确认、参考相似度与行为验证、benign control、候选级与项目级成功。

### 第 5 章：把 pilot、评委与可复现配置补到正文

1. **实验样本流，第 94–97 页。** 20 个案例、80 个输出对、97/97/77/91 的人评样本量之间缺少清楚对应。列原始漏洞、变体、模型输出、有效样本和排除理由，说明无输出如何进入成功率与相关性分析。
2. **评委协议，第 96–97 页。** 给出 1–5 分 rubric，LLM 评委聚合方式、分歧处理、人工是否盲评，以及评分究竟针对相似度、质量还是安全性。第 99 页已提 spot-check tests/static analysis，应给实际数量和结果。
3. **变换与污染，第 84–87 页。** 重命名和结构变换可用于测鲁棒性；现有证据尚不能量化训练污染减弱多少。收窄 bias mitigation 主张，并说明每种变换如何保持功能与漏洞语义。真实 CVE 与 CodeQL 示例的来源差异也应分层报告。
4. **RQ4 与 pilot，第 98–99 页。** 分类比例不能回答“first comprehensive benchmark”。将 RQ4 改为可检验的有效性问题，或定位为可行性演示。Pilot 核心样本量、原始/变换结果和代表性案例应进入正文，不能把核心结论完全外放到补充文档。
5. **配置与指标，第 90–99 页。** DeepCoder（deepcoder:14b）与 DeepSeekCoder 名称不一致，MLVBench/MLVulBench 混用；“latest versions”无法固定实验对象。列模型/backend、日期、采样与重试规则、prompt、代码版本。补 ELRM 的多参考聚合、短序列平滑、字面量配对和缺失组件处理。

### 第 6 章：补齐实验矩阵，并分开各类失败

1. **模型与输入配对，第 119–135 页。** 48 个生成实现、每个 repair model 仅 16 行结果，以及“for each project ... and repair model”的描述没有完全对应。明确 generator/detector/repairer 是否交叉，还是各模型只修自己生成的实现。若输入代码不同，模型间结果同时受输入难度影响，应限制能力排名式解释。
2. **测试可见性，第 135、141–144 页。** Test-inclusive 是合理的指导条件，不能简单称为不当泄漏；但提供的测试也用于最终评价，因此主要结论应限定为给定 oracle 上的收益。补充未公开攻击变体和 benign 边界案例，会显著加强根因修复的证据；不能补时，在条件专属的有效性威胁中说明测试暴露风险。
3. **基线未决与修复失败，第 131、141、171 页。** 全冻结套件含 baseline inconclusive，是已明确声明的严格口径。可保留 strict yield，但应额外区分原有不可评估检查、新功能回归、漏洞仍存在和基础设施问题。GPT P05 baseline B=0.00、P08 B=0.05 等尤其需要解释，不能把它们都读成模型修复能力失败。
4. **PrestaShop，第 152–153 页。** 三条件测试总数分别为 3778、3777、3774，且缺同清单的修复前状态。补固定 test inventory 和 baseline→post 转移，区分原有失败与新回归。保留“不满足整体 secure-and-correct”的现有表述；局部 VCT 通过不自动建立功能保留。
5. **不确定性，第 145–149、157 页。** 已写小样本与描述性分析，仍应给检测/修复 run 次数、预算、重试规则，以及项目级成功数和区间。“第二轮收益最大”只应描述本次轨迹，不应推成最优轮数规律。

### 第 7 章：改成跨研究综合，明确回答总论点

**第 175–178 页。** 当前主要重复三项研究摘要，并沿用旧范围结论。建议按三个总问题组织：什么安全现象被测量；哪些评估证据可信到什么程度；哪些干预带来改善、何时失败。每项都对应实际结果与边界。
